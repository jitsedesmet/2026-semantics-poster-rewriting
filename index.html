The gap
  • RDF 1.2 adds triple terms: one native way to state metadata about a statement
  • Published data keeps its own reification pattern — rdf:Statement, n-ary, custom
  • A federation has to speak all of them at once
Write SPARQL 1.2. Query the data you already have.
Mappings are just CONSTRUCT queries
1  Map the source onto the global schema
# rdf-reification → triple terms
CONSTRUCT { ?t rdf:reifies <<( ?s ?p ?o )>> }
WHERE { ?t a rdf:Statement ;
    rdf:subject ?s ; rdf:predicate ?p ;
    rdf:object ?o . }
# and pass everything else through
CONSTRUCT { ?s ?p ?o }
WHERE     { ?s ?p ?o }
2  Ask in SPARQL 1.2
SELECT * WHERE {
  ?t rdf:reifies <<( ?s rdf:type ?o )>> ;
     ex:confidence ?score .
  FILTER(?score > 0.8)
}

3  What the source actually gets
SELECT * WHERE {
  ?t a rdf:Statement ; rdf:subject ?s ;
     rdf:predicate rdf:type ; rdf:object ?o .
  ?t ex:confidence ?score .
  FILTER(?score > 0.8)
}
constants pushed into the mapping body · mappings that cannot match become FILTER(FALSE) and are pruned
